# Confidence Calibration: Measuring Threshold Reliability Across Document Quality

This harness measures whether Unsiloed's confidence scores and thresholds remain reliable as document quality degrades — answering three questions from Unsiloed's own "Confidence Score Reliability: The Missing Metric" blog:

1. **Which score to trust?** `grounding_score`, `extraction_score`, or `min(grounding, extraction)` — and do they predict correctness equally?
2. **Are scores well-calibrated?** Does a 0.9 confidence actually mean 90% accuracy, or does calibration drift as documents get harder?
3. **Do fixed thresholds survive document degradation?** The cookbook ships thresholds of 0.85 and 0.97 — do they hold on clean PDFs *and* on photographed documents?

## What you'll learn

- How to measure confidence score calibration reproducibly, without hand-labeling documents
- Why `grounding_score` and `extraction_score` are equally predictive for the "should I trust this?" decision
- How confidence scores become unreliable as documents degrade from clean PDFs → photographed pages
- Why a single global threshold (like 0.85) cannot work across document types

## Key Finding

**The same confidence threshold that works perfectly on clean PDFs becomes dangerously unsafe on poor-quality documents.** Using threshold 0.85:

- **Clean PDF (T0)**: 0% error on 96% of fields ✓
- **Photographed (T3)**: 33% error on 7% of fields ✗✗

## What's committed vs generated

- **`documents/*.pdf` and `*.truth.json`** (12 documents, 87KB) are committed. They are small and deterministic — `corpus/generate.py` reproduces them byte-for-byte from a fixed seed — so there is no reason to make a reviewer run anything just to see the corpus.
- **`documents/cord/`** (92 downloaded receipts, ~15MB) and **`documents/degraded/`** (derived tiers) are not committed, and are regenerated by `corpus/cord.py` and `corpus/degrade.py`. `samples/` carries a few committed examples instead:
  - `samples/degradation_ladder.png` — one invoice through all four tiers, side by side. The glare in T3 visibly wipes out the unit-price column, which is exactly the kind of damage this harness is built to catch.
  - `samples/cord/` — three real receipts from the CORD test split with their published ground truth (CC-BY-4.0, NAVER CLOVA AI Research), including the hand-shadow case referenced above.
- **`results/extractions/`** (140 cached API responses) is not committed; `results/figures/` and `results/*.csv` are, so the findings are visible without spending API quota.

## Quick start

```bash
# From the repo root
cp .env.example .env
# Edit .env and set UNSILOED_API_KEY

pip install -e .

cd confidence-calibration

# Generate the corpus (one-time)
python -m corpus.generate        # 12 synthetic documents with exact ground truth
python -m corpus.degrade         # Four degradation tiers (clean → photographed)
python -m corpus.cord            # Download 95 real CORD receipts (CC-BY-4.0)

# Extract documents (one-time, results cached)
python -m calibration.run

# Analyse (re-runnable, zero API calls)
python -m calibration.analyse

# Open the figures in results/figures/
```

Run times: corpus generation ~5s, degradation ~10s, CORD download ~3min, extractions ~5min, analysis ~30s.

## How it works

### The corpus

**Generated**: 12 synthetic documents (5 invoices, 4 statements, 3 ID cards) with exact ground truth by construction. No OCR, no labeling errors.

**Real**: 92 CORD receipts (CC-BY-4.0, published by NAVER CLOVA researchers) for external validity.

### The degradation ladder

Same documents, four quality tiers:

| Tier | What it is | Simulates |
|------|-----------|-----------|
| T0 | Original digital PDF | downloaded from a portal |
| T1 | Rasterised 150dpi, no text layer | printed and scanned |
| T2 | Plus 1.5° skew, sensor noise, blur | a tired office scanner |
| T3 | Plus perspective tilt, glare, shadows, JPEG q40 | photographed on a phone |

### The analysis

1. **Score discrimination**: Do grounding, extraction, or min(grounding, extraction) predict correctness better? Answer: they're equivalent (0.83 separation).

2. **Reliability diagram**: As document quality drops, do scores become miscalibrated? Answer: yes. T0/T1 hug the diagonal; T3 drifts wildly.

3. **Threshold sweep**: For each confidence threshold, what fraction auto-accepts and what's their error rate? Answer: T0 accepts 99% at 0.5 with 0% error; T3 accepts 70% at 0.5 with 40% error.

4. **Fixed thresholds**: Do the shipped thresholds (0.85, 0.97) work across all tiers? Answer: 0.85 breaks on T3 (33% error), 0.97 survives but only accepts 1%.

## Outputs

All cached in `results/`:

- **`figures/`**: Four PNG charts (discrimination, reliability, threshold sweep, fixed thresholds)
- **`scored_fields.csv`**: Every extracted field vs ground truth (2,307 rows)
- **`score_discrimination.csv`**: Which score predicts correctness
- **`calibration_error.csv`**: Expected calibration error per tier
- **`threshold_sweep.csv`**: Coverage and error per threshold per tier
- **`sub_1pct_thresholds.csv`**: Minimum threshold to hit <1% error per tier
- **`fixed_thresholds.csv`**: Error when using 0.85 and 0.97 across tiers

## Architecture

```
corpus/
  ├── generate.py              # Seeded synthetic document builder
  ├── degrade.py               # Four-tier degradation ladder
  ├── cord.py                  # CORD receipt downloader + reshaper
  └── schemas.py               # Extraction schemas (invoice, statement, ID, receipt)

calibration/
  ├── run.py                   # Extract every doc at every tier (resumable, cached)
  ├── compare.py               # Score fields against ground truth
  └── analyse.py               # Generate four outputs + figures

documents/
  ├── *.pdf                    # Generated PDFs (12 docs)
  ├── *.truth.json             # Ground truth (12 docs)
  ├── degraded/                # T1-T3 tiers (regenerated)
  └── cord/                    # CORD receipts (downloaded)

results/
  ├── extractions/             # Cached JSON responses (140 files, .gitignored)
  ├── figures/                 # PNG charts
  └── *.csv                    # Analysis tables
```

## Notes

- **Synthetic documents are realistic but controlled.** Exact ground truth and varied degradation are impossible with real documents. Validity depends on T0 being readable and T3 being genuinely hard (both visually verified).
- **CORD receipts are real but Indonesian.** Thermal paper, hand-written fields, shadows. Scores may not generalise to Western business documents; intent is external validity check.
- **Thresholds are specific to this corpus.** A company's documents may need different numbers. The *methodology* is the reusable part.
- **Scores drift between runs.** Unsiloed's models improve in production. Numbers are indicative; the *shape of findings* (thresholds don't travel) is durable.
